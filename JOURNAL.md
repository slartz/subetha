# Journal (newest first)

[2026-09-12] **Change — HTML reader, inline images, HTML quotes, and the owner/member model.** First real use surfaced four things at once. (1) HTML-only mail (an Outlook signature) rendered as text by default and its inline images were broken: they're `<img src="cid:…">` references to attached parts, which a sandboxed iframe cannot resolve. **Decision: inline them as `data:` URIs server-side** rather than serve parts by a route — a `sandbox` iframe has an opaque origin, so its subresource requests would not carry the Access cookie and a parts route would 401 from inside the frame. Parts are decoded on demand from the archived `.eml` (2 MB per image, 6 MB per message), remote images are neutralised to a placeholder until "Load N remote images" is clicked (never automatic — a shared address receiving from strangers is where tracking pixels live), and the HTML is sanitised on top of the sandbox with a CSP that allows only `data:` images. (2) Replies to HTML mail went out as `text/plain` with the stripped-text quote, so signature images became `[base64]` and links `text<url>`. **Decision: the author still types plain text, but a reply to an HTML original goes `multipart/alternative`** — text part with links as `text (url)` and images dropped, HTML part with the reply on top and the sanitised original in a `<blockquote>` with cid images removed so the reply stays self-contained. Stranger stylesheets are dropped from the quote (they would restyle the author's own text) though kept in the reader. Text-only originals still get text-only replies; compose stays text. (3) **Owners and members.** `OWNERS` var; identity is the Access JWT email, lowercased; the `ADMIN_SECRET` bearer is owner-equivalent and never a member. Owners see and administer everything; members — anyone on a mailbox's forward list — see, read, reply and compose on theirs and nothing else. Enforced server-side on every route: a message's row is fetched first and its mailbox checked before any byte is returned (unknown id → 404, not-yours → 403); `GET /api/me` and the mailbox list answer for everyone (empty for strangers) so the shell can render. Members can send as the mailbox, which means the unrestricted `send_email` is now reachable by non-owner logins — `sent_by` is recorded per message, so it is attributable. (4) Not changed: the DO schema (outbound HTML is not stored on the row; it is in the archived `.eml`), fan-out, loop guards. 97 tests; the reader's iframe behaviour was verified by hand against the exact CSP, since the route layer cannot load under `node --test`.

[2026-09-12] **Decision — auto-build from the private deployment repo, not from this one.** This repo ships placeholder vars on purpose; a Workers Builds trigger here would deploy a worker that locks everyone out, and every merged PR would deploy on click. The operator's private repo carries this one as a subtree with the real config outside it; Builds points there, path-filtered to the subtree and its config. Source public, deployment private, no token in the loop.

[2026-09-12] **Decision — SubEtha is a routing extender, not an inbox.** Owner's reframing after the survey, and it explains the empty niche better than "nobody thought of it": every other project starts from *inbox* and works backward; this starts from *Cloudflare Email Routing does one destination per address* and extends it. Point an address at the worker instead of a forward rule and get: (1) multiple destinations; (2) external destinations — re-originated from the mailbox, on the sending quota, with the DMARC caveat; (3) an archived copy in R2; (4) a place to skim, audit the fan-out, and act; (5) send/reply from the address; (6) rules — the loop guards are already the first ones, and a per-mailbox rule list that runs before fan-out (don't-forward, drop, tag) is the natural next feature, in the same "rules before models" shape the author uses elsewhere. Consequence for scope: the view is where you act and audit, never where you live — which is the line that keeps it small. "Rules", never "spam filter": a filter promises detection; rules promise a predicate. README and REQUIREMENTS to be reframed around this.

[2026-09-12] **Decision — own public repo, MIT, "provided as-is, fork freely".** Started inside the author's private infrastructure repo and moved out the same day, before its first commit. Reason: a survey of fourteen open-source "mailbox on Cloudflare" projects found that **nobody builds this combination**. Every project with storage + UI + native sending treats an address as a single-destination personal mailbox (`cloudflare/agentic-inbox`, `G4brym/email-explorer`, `hieunc229/mailflare`, `ufukayyildiz/omnidock`, `mucan54/cloudflare-mailbox`); every project that fans out to a list has no storage, no UI and no sending (`artlessconstruct`, `kenyonj`, two stale forwarders); `cloudflare_temp_email` has everything but is a disposable-address service in its data model. Two of the best mailboxes (`agentic-inbox`, `email-explorer`) *cannot* forward by construction — their `email()` takes the raw-stream signature, which has no `.forward()`; two carry a `forwarding` setting that nothing reads; `email-explorer`'s manual forward accepts an array of recipients and sends to the first only. And an address can route to exactly one target, so "mailbox + forward" cannot be assembled from two existing projects; it has to be one handler. Native sending to arbitrary recipients only exists since the **2026-04-16** Email Sending public beta, which is why older projects reach for Resend. The niche is therefore real but modest — *the small one*: fan-out + stored copy + reply, under 2,000 lines, no build step — and that is the pitch, not "first". Forking a webmail and adding ~400 lines of fan-out was weighed and declined for weight, not sunk cost: it means carrying a build pipeline, someone else's auth, and a patch in the inbound handler of an unfamiliar codebase. The day a real inbox is wanted, that's a fork of `email-explorer`, not a bigger SubEtha. Issues and PRs stay enabled so forks can flow back.

[2026-09-12] **Decision — fan-out is a hybrid, and it is the real design choice.** `message.forward()` preserves the original sender and costs nothing but only reaches Cloudflare-verified destination addresses; `send_email` reaches anyone but re-originates the message from the mailbox and draws on the sending quota. Members therefore carry a `mode`, chosen by the owner. Send mode sets `From: "<display>" <mailbox>` and `Reply-To: <original sender>` — the only arrangement that keeps SPF/DKIM/DMARC aligned; preserving the original `From:` on a re-originated message is what breaks DMARC. Member replies go to the original sender, not the list: this is a shared mailbox that also notifies people, not a discussion list, and reply-to-list is a non-goal.

[2026-09-12] **Decision — the `send_email` binding is deliberately unrestricted, and the wall is in the code.** Replying to a shared mailbox means replying to whoever wrote in, an address nobody can enumerate in advance, so `allowed_destination_addresses` cannot be used. Compensating control: `compose.js` is the only module that sends to a caller-chosen address; it is imported only by `index.js` and reached only through two authenticated routes; `inbound.js` — the whole `email()` path — does not import it and cannot reach it; `send.js` is the only module that touches `env.SEND`. `test/structure.test.mjs` walks the import graph and asserts all of that on every run. Any change to `inbound.js`'s imports is a change to the binding's blast radius.

[2026-09-12] **Decision — `email()` never throws and never `setReject`s.** A rejection is a bounce, and bounces damage the sending domain's reputation, which is shared with everything else that sends from it. Archive raw to R2 *before* parsing, so a parser bug costs a body and never the original; store even when the address has no configuration (`unconfigured=1`, surfaced in the UI) rather than dropping it. One DO call inserts the message and returns the members; fan-out runs in the worker, outside the object; one more call records results. The object does state, the worker does waiting.

[2026-09-12] **Decision — loop guards, and one deliberate non-guard.** Fan-out is suppressed for `Auto-Submitted` (any value but `no`), `Precedence: bulk|junk|list`, and our own `X-Subetha-Hop`; members equal to the mailbox or on a domain this worker itself routes (`ROUTED_DOMAINS`) are skipped. `List-Id` is deliberately **not** a guard — a shared mailbox subscribing to a list is legitimate. Known gap, from `mailflare`'s implementation: it also checks `X-Auto-Response-Suppress`, `X-Autoreply`, and `mailer-daemon`/`postmaster`/`no-reply` local parts, and stamps its own outbound `Auto-Submitted: auto-replied` so *other* systems recognise it. Ours stamps `X-Subetha-Hop`, which only we recognise. In the backlog, not bundled into v1.

[2026-09-12] **Problem — `validAddr` trimmed before matching.** `"a@b.co\r\n"` validated as true. No caller was exploitable (all trimmed first) but it was a landmine under the MIME builder's header-injection defence. Fixed by removing the trim; a test pins it.

[2026-09-12] **Problem — a first deploy attempt created an empty worker shell.** The deploy token lacked R2 read, so `wrangler deploy` failed on the bucket check — but an `&&` after a `| grep | tail` pipeline saw the pipe's exit status, not wrangler's, and ran `wrangler secret put`, which created a bare worker to hold the secret. Harmless (the next successful deploy overwrites it) but a reminder that `set -o pipefail` belongs in any chained deploy. Also: dashboard token edits take a minute or two to propagate; a probe that fails right after the edit is not proof the edit missed.

[2026-09-12] **Lesson — `grep -r` is blind to a file containing a NUL byte.** `test/build-mime.test.mjs` holds a literal NUL as a control-character fixture, so grep classifies the whole file as binary and prints nothing — not even "Binary file matches". Thirteen private references were hiding in there during the pre-publication scrub. Use a UTF-8-aware scan (`grep -a`, or `rg`) for any "is this clean?" check on this repo; documented in TESTS.md and AGENTS.md.
